MOCKUP ROUND 05 · 2026-04-15 · LEVEL 1-4 + REAL VOICES

Presets map to Valve Levels. Voices drive the spec.

The four curated presets now map 1:1 to Valve's Steam Deck performance overlay Level 1-4 — Minimal · Standard · Advanced · Full — because every surveyed handheld gamer already understands this vocabulary. Manual is demoted to a quiet "Or build your own ▸ Manual" link below the preset row and starts as a copy of whichever curated preset was last active (users want to tweak, not rebuild from empty). Standard is the mass-market sweet spot per Windows Central, MakeUseOf and the Valve FPS-only patch. The spec's §2b is now written entirely from real quotes — Steam Community Bug Reports, g-helper and HandheldCompanion GitHub issues, Steam Deck HQ, XDA, GamingOnLinux, PulseGeek — not generic UX laws. Full research: docs/superpowers/research/handheld-gamer-voices.md.

CODE · HHAP-0.5 audit
The HUD is clean. The companion window is the mess.

MainWindow.xaml + TopBarControl.xaml are rule-compliant and stay. The mess lives in HubView.xaml (preset cards, nested ellipses, dead Live-now strip), ComposerOverlay.xaml (the whole wizard), and SupportView.xaml (Advanced diagnostics expander). Tokens in HhapTheme.xaml are healthy — reuse them.

PLATFORM · WinUI 3
No cheap frosted-glass cards.

Mica/Acrylic are window-level only in WinUI 3. Per-element frosted cards require DirectComposition plumbing we want to avoid. Custom fonts, color transitions, page transitions, and Lightweight Styling are all free. Shadows are popup-first — prototype before relying on them.

Decision: Direction A is the default skin. Directions B and C were cut from the mockup after a side-by-side review — B felt too clinical for the brand's warm tinkerer voice, C's per-element glass is not cheaply achievable in WinUI 3 and the brand reserves glass+gold for the future Founder tier anyway. Operator details from B (pulsing capture dot, mono numerics on HUD, faint cyan grid on data surfaces, corner ticks) are being folded into A. C is deferred until we ship a Founder unlock.

Handheld psychology — 7 principles we're designing to

  1. The user paused a game. Every second of chrome is stolen from play. The companion opens → the two knobs that matter are already visible → one click each → resume. Fitts's + Hick's laws. Miller 7±2 metric count.
  2. Handhelds are read at arm's length. Body type floors at 0.875rem, numerals at 1.25rem. Band-tier dots glow so they read in peripheral vision on a 7" screen at 40 cm. WCAG 2.2 reading distance + contrast AA on dark surfaces.
  3. Battery and thermals are constant anxieties. Battery % sits in the topbar chip row — always visible, never hidden behind a tab. Live FPS sits next to it. CPU/GPU % tell the user how close to thermal headroom they are. Handheld mental-model primary concerns. Brand voice: "the ally whispering stats".
  4. Touch + gamepad + mouse, all at once. Every interactive target is ≥ 2.75rem (~44 dip). Tab order matches visual order. Focus ring is brand-cyan so it's legible on dark slate. MS Fluent accessibility spec; XYFocusKeyboardNavigation=Enabled.
  5. No fluff, no marketing. The product surface shows status + knobs + status. Marketing copy ("Stop glancing. Just play.") ships in the Store listing, not in the app. Brand lives in typography, colour, motion — not headlines. Johny 2026-04-15: "just open and work, no fluff and marketing around it".
  6. Session memory. Short sessions, interrupted. The app always opens in whatever state the user left it. No "welcome back" dialog, no onboarding on second launch. Kahneman attention restoration. Every competing launcher does this wrong.
  7. Thermal / battery context in the event line. A single muted mono line at the bottom of the work area shows pid · exe · frametime · sample rate — pro diagnostic info without cluttering the main surface. This is the one Command-Deck detail that survived the rewrite. Progressive disclosure; visible-but-quiet.
